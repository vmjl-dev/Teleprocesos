Introducción al Teleproceso Moderno

El teleproceso es el resultado de la conjunción de dos palabras: TELE (a distancia) y PROCESO (ejecución sistemática de un conjunto de instrucciones para capturar, transformar y generar información). Por tanto, el teleproceso se define como la ejecución de una aplicación de forma remota mediante el uso de una red de comunicación de datos. Esta tecnología está intrínsecamente asociada con las redes de comunicación de datos y representa uno de los pilares fundamentales de la informática moderna.

El teleproceso existe en múltiples aplicaciones de la vida cotidiana que cumplen con esta definición: telemedicina, telemetría, banca en línea, sistemas de reservas, comercio electrónico y prácticamente cualquier aplicación que permita la interacción bidireccional entre un usuario y un sistema de procesamiento ubicados en lugares diferentes.

Arquitectura Cliente-Servidor en Teleproceso

La arquitectura cliente-servidor es un modelo de diseño fundamental en teleproceso donde las tareas se reparten entre los proveedores de recursos (servidores) y los demandantes (clientes). En este modelo:

El cliente

Inicia solicitudes de manera activa, espera y recibe las respuestas del servidor, puede conectarse a varios servidores simultáneamente y normalmente interactúa con los usuarios finales mediante una interfaz gráfica.

El servidor

Espera pasivamente las solicitudes de los clientes, procesa cada solicitud recibida y envía la respuesta correspondiente, acepta conexiones de múltiples clientes de forma concurrente y centraliza la gestión de recursos y aplicaciones.

El funcionamiento sigue este proceso: el cliente realiza una solicitud de recurso o servicio al servidor a través de la red, el servidor recibe y procesa la entrada de datos, compone una respuesta y la envía por la red hasta llegar al cliente, quien la recibe y muestra una salida adecuada para el usuario.

Las ventajas de esta separación de responsabilidades incluyen la posibilidad de escalar o mantener las aplicaciones por separado, facilitar la creación de equipos de trabajo independientes y utilizar infraestructuras especializadas para cada componente.

Modelo OSI/ISO: Fundamento Teórico de las Comunicaciones

El Modelo de Interconexión de Sistemas Abiertos (OSI) fue desarrollado por la Organización Internacional de Normalización (ISO) a finales de la década de 1970, publicándose en su primera versión en 1984 como ISO 7498. Este modelo proporciona un marco conceptual teórico que describe las funciones de un sistema de red mediante siete capas de abstracción.

Nota importante: El modelo OSI es principalmente un referente teórico, mientras que el modelo TCP/IP es el que realmente se implementa en Internet y redes modernas.

Las Siete Capas del Modelo OSI

Capa 7 - Capa de Aplicación

Ofrece a las aplicaciones la posibilidad de acceder a los servicios de las demás capas y define los protocolos que utilizan las aplicaciones para intercambiar datos. Los protocolos principales incluyen:

  • HTTP/HTTPS: para acceso a páginas web
  • FTP: para transferencia de archivos
  • SMTP: para envío de correo electrónico
  • POP/IMAP: para recuperación de correo electrónico
  • DNS: para resolución de nombres de dominio
  • DHCP: para configuración dinámica de hosts

El usuario normalmente no interactúa directamente con esta capa, sino con programas que interactúan con ella ocultando la complejidad subyacente.

Capa 6 - Capa de Presentación

Prepara los datos para que puedan mostrarse al usuario, actuando como traductor. Es responsable de la codificación y descodificación de información (como el cifrado HTTPS), la compresión y descompresión de datos, y la sintaxis de los datos mismos. Formatos como HTML, JSON y CSV operan en esta capa.

Capa 5 - Capa de Sesión

Gestiona y controla las sesiones de comunicación entre aplicaciones. Establece, mantiene y finaliza las conexiones entre aplicaciones, controlando los diálogos y la sincronización.

Capa 4 - Capa de Transporte

Proporciona servicios de comunicación de extremo a extremo para las aplicaciones. Divide los datos en segmentos, asigna números de secuencia para asegurar el orden correcto en la recepción y gestiona el control de flujo y errores. Los protocolos principales son:

  • TCP (Transmission Control Protocol): protocolo orientado a conexión que garantiza la entrega fiable y ordenada de datos mediante confirmación de recepción y retransmisión de paquetes perdidos
  • UDP (User Datagram Protocol): protocolo no orientado a conexión, más rápido pero sin garantías de entrega ni control de errores

TCP es adecuado para aplicaciones que requieren entrega confiable (correo electrónico, navegación web), mientras que UDP se usa para aplicaciones en tiempo real donde la velocidad es prioritaria (video en vivo, videojuegos, VoIP).

Capa 3 - Capa de Red

Proporciona conectividad y selección de ruta entre sistemas ubicados en redes geográficamente distintas. Sus funciones principales incluyen:

  • Direccionamiento: proporciona mecanismos para direccionar datos a equipos finales mediante direcciones IP
  • Encapsulamiento: agrega encabezados con direcciones de origen y destino, convirtiendo segmentos en paquetes
  • Enrutamiento: determina la ruta más rápida y eficaz para llegar al destino
  • Desencapsulamiento: lee y procesa los encabezados de los paquetes recibidos

Existen dos versiones del Protocolo de Internet: IPv4 (4,294,967,296 direcciones) e IPv6 (3.4 × 10³⁸ direcciones, suficiente para miles de direcciones por cada metro cuadrado de la Tierra).

Capa 2 - Capa de Enlace de Datos

Gestiona las tecnologías para conectar dos máquinas a través de una red donde la capa física ya existe. Controla los marcos de datos, implementa control de flujo y control de errores, y agrega direcciones locales (MAC) de origen y destino a las tramas. Ethernet es el estándar más común en esta capa.

Capa 1 - Capa Física

Se refiere al medio de comunicación físico y las tecnologías para transmitir datos a través de ese medio. Incluye el equipo físico (cables, conmutadores de red) y convierte las tramas en una secuencia de bits (unos y ceros) para su transmisión a través de medios físicos. Las tecnologías incluyen Bluetooth, NFC, cables de cobre, fibra óptica y transmisión inalámbrica.

Proceso de Comunicación en el Modelo OSI

Cuando un usuario envía un correo electrónico a otro usuario, los datos atraviesan las siete capas en orden descendente en el dispositivo emisor y luego en orden ascendente en el receptor:

  1. La aplicación de correo pasa el mensaje a la capa de aplicación, que selecciona el protocolo SMTP
  2. La capa de presentación comprime y cifra los datos si es necesario
  3. La capa de sesión inicia la sesión de comunicación
  4. La capa de transporte segmenta los datos y agrega números de secuencia
  5. La capa de red fragmenta los segmentos en paquetes y agrega direcciones IP
  6. La capa de enlace de datos divide los paquetes en tramas y agrega direcciones MAC
  7. La capa física convierte las tramas en señales eléctricas, ópticas o electromagnéticas que viajan a través del medio físico

Encapsulamiento de Datos

El encapsulamiento es el proceso por el cual los datos se colocan en paquetes administrables y rastreables. Cada capa agrega su propio encabezado con información de control, creando unidades de datos de protocolo (PDU) específicas:

  • Datos: en las capas de aplicación, presentación y sesión
  • Segmentos: en la capa de transporte
  • Paquetes: en la capa de red
  • Tramas: en la capa de enlace de datos
  • Bits: en la capa física

En el receptor, el proceso inverso (desencapsulamiento) elimina sucesivamente cada capa de encabezados hasta recuperar los datos originales.

Ventajas y Desventajas del Modelo OSI

Ventajas:

  • Facilita la comprensión al dividir un problema complejo en partes más simples y manejables
  • Normaliza los componentes de red permitiendo la interoperabilidad entre diferentes fabricantes
  • Evita problemas de incompatibilidad al establecer estándares claros
  • Permite el desarrollo y mantenimiento independiente de cada capa
  • Facilita la detección y resolución de problemas de red al aislar funciones por capas

Desventajas:

  • Tuvo mala sincronización con el desarrollo de TCP/IP, que se adoptó más ampliamente
  • Presenta funciones repetidas en diferentes capas, generando redundancia
  • Mayor complejidad conceptual comparado con modelos más simples
  • No se implementa directamente en la práctica; TCP/IP es el estándar real

Principios de Transmisión de Datos

La transmisión de datos es la transferencia física de datos (un flujo digital de bits) por un canal de comunicación punto a punto o punto a multipunto. Los datos se representan como señales electromagnéticas: tensión eléctrica, ondas radioeléctricas, microondas o infrarrojos.

Componentes Básicos de un Sistema de Transmisión

Todo sistema de transmisión de datos consta de los siguientes elementos fundamentales:

  1. Fuente de información: origen de los datos a transmitir
  2. Transductor: convierte la información en señales eléctricas digitales, agrega redundancia e información de control
  3. Transmisor: interfaz entre el transductor y el canal, transforma las señales digitales en formas compatibles con el canal mediante técnicas de modulación (MODEM)
  4. Canal de transmisión: medio físico (cable telefónico, par trenzado, coaxial, fibra óptica, radio, infrarrojos) por donde viajan las señales
  5. Receptor: recibe y decodifica las señales del canal
  6. Destino: receptor final de la información

Tipos de Transmisión

Transmisión Analógica

Las señales se caracterizan por el cambio continuo de amplitud. En ingeniería de control de procesos, la señal oscila entre 4 y 20 mA y se transmite en forma puramente analógica. El contenido de información es restringido, limitándose al valor de la corriente y su presencia o ausencia.

Transmisión Digital

Las señales no cambian continuamente, sino que se transmiten en paquetes de datos discretos. No son interpretadas inmediatamente, sino que deben ser decodificadas por el receptor. Se transmiten como pulsos eléctricos que varían entre dos niveles distintos de voltaje. Ofrece mayor inmunidad al ruido y permite corrección de errores.

Modos de Transmisión

Transmisión Símplex

Permite la transmisión de datos en una sola dirección, sin posibilidad de retorno. Un dispositivo siempre actúa como fuente y el otro como receptor. Ejemplos: transmisión de televisión tradicional, radiodifusión, comunicación entre computadora e impresora.

Ventajas: dispositivos sencillos, comunicación directa sin estaciones intermedias.

Desventajas: solo apto para redes simples de pequeña capacidad, comunicación unidireccional limitada.

Transmisión Half-Duplex (Semidúplex)

Permite la transmisión en ambas direcciones, pero no simultáneamente. Ambos lados pueden transmitir y recibir datos, pero en momentos diferentes, alternando la dirección de transmisión. Ejemplo: walkie-talkies, donde se dice "cambio" para indicar el fin de la transmisión.

Ventajas: conserva ancho de banda al necesitar solo un canal para transmisión alternada.

Desventajas: pérdida o distorsión si más de una parte transmite simultáneamente, velocidad de transmisión baja debido a retrasos por conmutación.

Transmisión Full-Duplex (Dúplex Completo)

Permite que ambos dispositivos transmitan y reciban datos simultáneamente. Requiere dos canales de comunicación independientes o técnicas de cancelación de eco. Ejemplo: conversación telefónica moderna, redes Ethernet Gigabit.

Ventajas: alta eficiencia, permite comunicación bidireccional simultánea.

Desventajas: mayor costo y complejidad técnica.

Ancho de Banda y Tasa de Transferencia

Ancho de Banda

El ancho de banda se mide como la cantidad de datos que se pueden transferir entre dos puntos de una red en un tiempo específico. Normalmente se mide en bits por segundo (bps) y se expresa como tasa de bits. Representa la capacidad de transmisión de una conexión y es un factor importante para determinar la calidad y velocidad de una red.

Tipos de ancho de banda:

  • Máximo teórico: tasa de transmisión más alta en circunstancias ideales, no alcanzable en instalaciones físicas reales
  • Ancho de banda efectivo: cifra de velocidad de transmisión fiable más alta, siempre menor que el máximo teórico
  • Rendimiento (throughput): tasa media de transferencia de datos exitosa, valor útil para comprender la velocidad típica

Tasa de Transferencia de Datos

La tasa de transferencia se refiere a la velocidad a la que los datos se transmiten entre dispositivos o a través de una red. Se mide en bits por segundo (bps), bytes por segundo (Bps) o sus múltiplos: Kbps (kilobits), Mbps (megabits), Gbps (gigabits).

Un mayor ancho de banda generalmente permite tasas de transferencia más altas, ya que se pueden transmitir más datos simultáneamente.

Medios de Transmisión

Cable de Par Trenzado

Consiste en pares de cables de cobre o aluminio aislados enrollados entre sí para reducir la interferencia eléctrica y la diafonía. Existen dos tipos principales:

  • UTP (Par Trenzado No Apantallado): sin blindaje adicional, más económico
  • STP (Par Trenzado Apantallado): con cubierta de papel de aluminio para eliminar interferencias

Categorías comunes: Cat5e (1 Gbps, 100 MHz), Cat6 (10 Gbps a 55m, 250 MHz), Cat6a (10 Gbps a 100m, 500 MHz), Cat7 (10 Gbps, 600 MHz), Cat8 (25/40 Gbps, 2000 MHz). Distancia máxima típica: hasta 100 metros.

Cable Coaxial

Compuesto por un conductor sólido interior rodeado por un conductor de lámina exterior paralelo protegido por una capa aislante. Tiene mayor capacidad de transmisión y mejor inmunidad al ruido que el par trenzado. Se utiliza para señales de video (75 ohmios) y transmisión de datos bidireccional (50 ohmios). Distancia máxima: hasta 500 metros.

Fibra Óptica

Transmite datos mediante pulsos de luz a través de pequeños tubos de vidrio o plástico. Ofrece un ancho de banda significativamente mayor que los cables de cobre y es inmune a interferencias electromagnéticas. Tipos:

  • Fibra monomodo (SMF): núcleo pequeño (8-10 μm), solo un modo de propagación de luz, distancia de hasta 80-100 km
  • Fibra multimodo (MMF): núcleo más grande (50-62.5 μm), múltiples rayos de luz, distancias variables según categoría (OM3/OM4: hasta 550m en redes 10G)

Velocidades: desde 10/100/1000 Mbps hasta 10/40/100/200 Gbps.

Sincronización de Transmisiones

Transmisión Asíncrona

En la transmisión asíncrona, el proceso de sincronización entre emisor y receptor se realiza en cada palabra de código transmitido. No hay relación temporal constante entre transmisor y receptor; cada uno utiliza su propio reloj.

Características:

  • Los datos se transmiten por caracteres o bytes individuales
  • Cada carácter está precedido por un bit de arranque (start) que sincroniza el reloj del receptor
  • Finaliza con uno o más bits de parada (stop) que separan caracteres consecutivos
  • Puede incluir un bit de paridad para verificación de errores
  • Entre dos caracteres consecutivos puede haber intervalos irregulares
  • Rendimiento típico alrededor del 70-80% debido a bits de control

Ventajas: simple implementación, adecuada para flujo irregular de datos, recuperación rápida de errores.

Desventajas: menor eficiencia debido a bits de overhead, limitada para altas velocidades.

Transmisión Síncrona

En la transmisión síncrona se mantiene sincronización continua entre emisor y receptor, generalmente mediante una señal de reloj compartida o recuperada de la señal de datos.

Características:

  • Los datos se agrupan en bloques formando tramas con tamaño y estructura determinados
  • Cada trama comienza con patrones de sincronismo (SYN) y termina con secuencias de fin de bloque
  • Los bloques típicamente tienen entre 128 y 4,096 bytes
  • Rendimiento muy alto (superior al 95-99%)
  • Más eficiente e inmune a errores que la asíncrona
  • Requiere circuitos más complejos para sincronización

Ventajas: alta eficiencia de transmisión, apta para altas velocidades, mejor detección de errores.

Desventajas: mayor complejidad tecnológica, requiere buffers para datos.

Control de Errores

Bit de Paridad

El bit de paridad es el método más simple de detección de errores. Se agrega un bit adicional a cada carácter para que la cantidad total de bits "1" sea par (paridad par) o impar (paridad impar). El receptor verifica la paridad de cada unidad de entrada de datos.

Limitaciones: solo puede detectar un número impar de errores; si ocurren dos bits erróneos, no se detecta el error, detectando aproximadamente el 50% de los errores.

Prueba de Paridad Vertical y Horizontal (VRC/LRC)

La paridad vertical (VRC) aplica la prueba de paridad a cada carácter de un bloque de datos. La paridad horizontal o longitudinal (LRC) se utiliza para determinar si ocurrió un error en un mensaje completo compuesto por caracteres. La secuencia de dígitos en el LRC se calcula en el transmisor y se transmite como el último carácter del mensaje (carácter BCC). En el receptor, el BCC se recalcula y se compara con el BCC transmitido.

CRC (Cyclic Redundancy Check) - Comprobación de Redundancia Cíclica

El CRC es una técnica robusta para detectar errores de ráfaga (múltiples bits consecutivos). Utiliza operaciones matemáticas polinomiales para generar un código de verificación que se agrega a los datos transmitidos. En la recepción, se recalcula el CRC y se compara con el transmitido para verificar la integridad de los datos. Puede detectar el 99.99% de los errores.

Técnicas de Conmutación

Conmutación de Circuitos

Basada en los principios de los sistemas telefónicos tradicionales. Establece una conexión física dedicada entre los nodos de red por toda la duración de la comunicación. El proceso incluye tres fases: establecimiento del circuito, transferencia de datos y cierre del circuito.

Ventajas: baja latencia una vez establecido, recursos dedicados, ideal para comunicación en tiempo real (voz).

Desventajas: uso ineficiente del canal cuando no hay transmisión activa, requiere tiempo para establecer la conexión, no flexible para tráfico de datos variable.

Conmutación de Mensajes

Los mensajes se transmiten como una entidad completa de un nodo a otro. Cada nodo intermedio almacena el mensaje completo antes de reenviarlo al siguiente nodo (almacenamiento y reenvío).

Ventajas: no requiere establecimiento previo de circuito, permite priorización de mensajes.

Desventajas: retrasos significativos en la entrega, requiere gran capacidad de almacenamiento en los nodos, poco eficiente para mensajes largos.

Conmutación de Paquetes

La información se divide en unidades más pequeñas llamadas paquetes. Cada paquete contiene un encabezado con información de control necesaria para enrutarlo desde el origen hasta el destino. Los paquetes se transmiten de manera independiente a través de la red y pueden seguir diferentes rutas hacia su destino.

Dos técnicas principales:

  • Datagrama: cada paquete se encamina independientemente, pudiendo llegar en desorden o perderse
  • Circuito virtual: se establece un camino lógico antes de enviar los paquetes, todos los paquetes siguen la misma ruta

Ventajas: multiplexación estadística que permite compartir eficientemente los enlaces, múltiples flujos de datos transmitidos simultáneamente, uso más eficiente del ancho de banda, robustez ante fallos.

Desventajas: posibles retrasos o descarte de paquetes en caso de congestión, mayor complejidad en el procesamiento, overhead por encabezados.

La conmutación de paquetes se ha convertido en la base principal de las comunicaciones de datos en redes informáticas a nivel mundial, siendo el fundamento de Internet.

Topologías de Red

Topología de Bus

Todos los dispositivos están conectados a un único cable (bus) que actúa como medio de transmisión compartido. La transmisión es half-duplex - los dispositivos deben turnarse para transmitir.

Ventajas: fácil implementación, bajo costo, adecuada para redes pequeñas.

Desventajas: si falla el bus central, toda la red falla; el rendimiento disminuye con muchos dispositivos; difícil detección de fallas; problemas de colisiones.

Topología de Estrella

Todos los dispositivos se conectan a un dispositivo central (switch o hub). Cada nodo tiene una conexión directa con el dispositivo central, que dirige el tráfico entre nodos.

Ventajas: fácil detección y aislamiento de fallas, escalable, alto rendimiento, fácil configuración y mantenimiento.

Desventajas: dependencia del nodo central (punto único de fallo), requiere más cable que la topología de bus.

Topología de Anillo

Los dispositivos están conectados en un lazo cerrado donde cada nodo se conecta al siguiente y el último al primero. Los datos se envían en una dirección alrededor del anillo, con cada nodo regenerando la señal.

Ventajas: flujo de datos ordenado y controlado, sin colisiones de datos, rendimiento predecible.

Desventajas: si falla un nodo o un enlace, puede afectar toda la red; difícil agregar o quitar dispositivos; menos común en redes modernas.

Topología de Malla

Cada nodo está conectado a múltiples o todos los demás nodos de la red. Proporciona múltiples rutas para que los datos viajen de un punto a otro.

Ventajas: alta redundancia y resiliencia, no hay punto único de fallo, múltiples rutas alternativas, excelente para redes de misión crítica.

Desventajas: muy costosa, difícil instalación y mantenimiento, requiere gran cantidad de cables o interfaces.

Topología Híbrida

Combina dos o más topologías diferentes para aprovechar las fortalezas de cada una. Ejemplo: topología de estrella dentro de cada departamento, conectados mediante topología de anillo o malla.

Seguridad en Teleproceso

Cifrado

El cifrado es el proceso de convertir datos legibles (texto plano) en un formato codificado (texto cifrado) que solo puede ser leído por quienes poseen la clave de descifrado.

Beneficios del cifrado:

  • Privacidad: solo remitente y destinatario pueden leer los datos
  • Seguridad: previene vulneraciones de datos
  • Integridad: evita manipulación de datos durante la transmisión
  • Cumplimiento normativo: muchas regulaciones (HIPAA, PCI-DSS, RGPD) requieren cifrado

Tipos principales de cifrado:

  • Cifrado simétrico: usa la misma clave para cifrar y descifrar. Algoritmos: AES (estándar actual), ChaCha20
  • Cifrado asimétrico: usa par de claves (pública y privada). Algoritmos: RSA, criptografía de curva elíptica (ECC)

TLS (Transport Layer Security)

TLS es el protocolo de cifrado más utilizado para asegurar comunicaciones en Internet. Funciona estableciendo una conexión segura mediante:

  • Handshake de TLS: cliente y servidor acuerdan protocolos de cifrado usando criptografía asimétrica
  • Autenticación con certificados digitales: el servidor prueba su identidad
  • Intercambio de claves: se establece una clave de sesión segura
  • Comunicación cifrada: todos los datos se cifran usando cifrado simétrico de alto rendimiento (como AES)

Características clave de TLS:

  • Algoritmos de cifrado fuertes (AES, ChaCha20)
  • Infraestructura de Clave Pública (PKI) para autenticación
  • Secreto hacia adelante (forward secrecy)
  • Verificación de integridad mediante HMAC
  • Soporte para múltiples versiones de protocolo (TLS 1.2, TLS 1.3)

Autenticación

La autenticación verifica la identidad de usuarios y dispositivos antes de permitir acceso a recursos.

Mejores prácticas:

  • Autenticación multifactor (MFA): requiere al menos dos factores de autenticación (contraseña + token + biometría)
  • Autenticación sin contraseña: uso de claves de seguridad FIDO2, Windows Hello, etc.
  • Implementación de certificados digitales para servidores y clientes
  • Control de acceso basado en roles (RBAC)
  • Monitoreo continuo de accesos

Conclusión

Los fundamentos del teleproceso moderno se sustentan en una arquitectura robusta de comunicaciones que integra el modelo OSI/ISO como marco conceptual teórico, diversos principios de transmisión de datos y múltiples tecnologías de red. Si bien el modelo OSI proporciona una estructura lógica de siete capas que facilita la comprensión de las comunicaciones de red, es el modelo TCP/IP el que realmente se implementa en Internet y redes modernas.

La arquitectura cliente-servidor constituye el paradigma fundamental del teleproceso, permitiendo la distribución eficiente de recursos y procesamiento entre múltiples usuarios y sistemas. Las técnicas de modulación, sincronización, control de errores y conmutación trabajan conjuntamente para asegurar la integridad y disponibilidad de los datos transmitidos.

La seguridad mediante cifrado robusto (AES, TLS 1.3) y autenticación multifactor se ha vuelto un componente crítico del teleproceso moderno, protegiendo la confidencialidad, integridad y disponibilidad de la información en tránsito. La evolución continua de estos fundamentos, junto con el desarrollo de nuevas tecnologías como 5G, IoT y computación en la nube, impulsa el desarrollo de aplicaciones cada vez más sofisticadas que transforman la manera en que trabajamos, nos comunicamos y accedemos a la información en la era digital.
